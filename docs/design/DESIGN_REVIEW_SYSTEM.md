# Clearpath Systems — Design Review Workflow

The purpose of this workflow is to prevent visual and UX drift while preserving the Clearpath Systems brand identity.

This process exists to:
- reduce generic SaaS patterns
- prevent unnecessary UI complexity
- preserve operational clarity
- maintain calm, practical visual language
- keep interfaces aligned with real operational workflows

The workflow is intentionally lightweight.

---

# Review Flow

## 1. Implementation Pass

A design or UI change is proposed and implemented.

This may include:
- layout changes
- typography adjustments
- spacing changes
- interaction updates
- homepage/product page refinement
- component additions/removals

The implementation pass should focus on solving the problem directly without premature optimization or excessive polish.

---

## 2. Adversarial Review Pass

The adversarial reviewer critiques the implementation from the perspective of brand integrity and operational clarity.

The reviewer should identify:
- SaaS drift
- unnecessary chrome
- visual clutter
- weak hierarchy
- over-animation
- decorative complexity
- inflated marketing behavior
- operational ambiguity
- cognitive overload

The reviewer does NOT redesign the interface.
The reviewer identifies problems and explains why they violate the Clearpath Systems philosophy.

---

## 3. Synthesis Pass

The synthesis pass evaluates the adversarial feedback.

Goals:
- preserve grounded critique
- reject unnecessary overcorrection
- maintain momentum
- improve clarity without creating complexity

The synthesis pass should:
- apply useful refinements
- preserve strengths of the implementation
- avoid oscillation between extremes
- protect overall design cohesion

---

# Design Philosophy

Clearpath Systems interfaces should feel:
- calm
- practical
- operational
- trustworthy
- structured
- low-friction

The design should support:
- attention scarcity
- interruption-heavy workflows
- operational clarity
- human-supervised systems

---

# Core Anti-Drift Rules

Avoid:
- generic SaaS landing page patterns
- excessive card/border usage
- visual noise
- fake dashboards
- hype-driven copy
- decorative complexity
- unnecessary interaction layers
- over-designed animation
- “AI magic” aesthetics

Prefer:
- whitespace
- typography hierarchy
- restrained motion
- practical layouts
- operational clarity
- simple interaction patterns
- grounded visual language

---

# Guiding Principle

The interface should feel like a useful operational surface, not a marketing performance.
